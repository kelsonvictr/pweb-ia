💡 A frase que resume a web inteira

Navegador pede (request) → servidor responde (response). Instagram, YouTube, banco, joguinho… tudo que você abre na internet é essa conversa acontecendo, milhões de vezes por segundo.

💡 localhost = "aqui mesmo"

localhost é o apelido que todo computador dá pra si mesmo. Quando você acessa localhost:5000, o navegador faz um request… pro seu próprio computador. Mesa e cozinha na mesma casa — perfeito pra desenvolver sem depender de internet.

As linguagens do navegador

Antes de servir páginas, você precisa saber do que uma página é feita

🧱
HTML: a língua que o navegador entende
A response que o servidor manda é escrita nela

Quando o garçom volta com o "prato" (a response), o que vem dentro do pacote? Não é uma foto da tela pronta. É texto — texto escrito numa língua chamada HTML, que o navegador lê e transforma em página.

Texto com etiquetas 🏷️

HTML é um texto normal onde cada pedaço ganha uma etiqueta dizendo o que ele é: "isto é um título", "isto é um parágrafo", "isto é uma lista". O navegador lê as etiquetas e desenha cada coisa do jeito certo. As etiquetas se chamam tags.

🔬 Anatomia de uma tag

uma tag de título HTML 
<h1>Minha Loja</h1>
 ↑ abre           ↑ conteúdo   ↑ fecha (repare na barra /)
💡 A regra do sanduíche

Quase toda tag vem em par: abre <h1>, recheio no meio, fecha </h1> — a de fechar tem uma barra /. O que está entre as duas é o conteúdo.

As 4 tags que você vai usar hoje (só 4, prometo):

📰 <h1> título principal da página (h de heading)
📝 <p> parágrafo de texto comum
📋 <ul> + <li> lista (ul) e cada item dela (li)
🔗 <a> link pra outra página (vai brilhar no fim da aula)

🪆 Tags dentro de tags

Tags podem se aninhar, como bonecas russas. Uma lista é isso: itens <li> morando dentro de um <ul>:

lista de produtos HTML 
<ul>
  <li>🎧 Fone Bluetooth</li>
  <li>⌨️ Teclado Mecânico</li>
</ul>
⚠️
Regra das bonecas: quem abre por último, fecha primeiro. O <li> abriu dentro do <ul>, então fecha antes do </ul>. Cruzar tags (<ul><li></ul></li>) confunde o navegador.

CSS: a roupa da página (e um truque de mestre)
Sua página funciona… mas tá com cara de 1996, né? 😅
Estrutura vs. aparência 👔

O HTML diz O QUE existe na página (título, lista, link) — é o corpo. O CSS diz COMO cada coisa aparece (cor, tamanho, espaçamento) — é a roupa. São duas linguagens separadas, cada uma com um trabalho.

Escrever CSS bonito dá trabalho e é uma arte à parte (é metade do curso Fullstack, pra você ter ideia). Mas existe um truque de gente esperta: usar uma folha de estilo pronta. Aperte o botão e veja o que UMA linha de HTML faz:

Bora aplicar: uma linha no head
Pico.css — estilo pronto, de graça, direto da internet

Dentro do <head> da sua página (pode ser logo abaixo do <title>), adicione esta linha:

loja/index.html (dentro do head) HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@picocss/pico@2/css/pico.min.css">

Salve, dê F5… e pronto: tipografia, cores e espaçamento de gente grande. 😎

🔍
Traduzindo a linha: <link> conecta um arquivo externo à página; rel="stylesheet" avisa que é uma folha de estilo; href diz o endereço dela na internet. O navegador baixa e aplica sozinho.
🧭
Neste curso, CSS é isso: uma linha. O Pico cuida do visual e a gente foca no Python. Quer dominar CSS de verdade (layouts, animações, design)? Esse é o território do curso Fullstack — te espero lá depois. 😉

Seu primeiro servidor: 7 linhas de Python
Acompanhe o destaque passando por cada linha — sem pressa

Botão direito na pasta loja → New → Python File, nome app.py (do lado do index.html). Este é o programa inteiro — e ele é um servidor web completo:

loja/app.py Python 
from flask import Flask app = Flask(__name__) @app.route("/")def home():    return "Minha Loja no ar! 🎉" app.run(debug=True)
📦Importa a Flask, a peça que sabe ser um servidor web. Igualzinho você importava o TinyDB.
🍳Cria a sua "cozinha": app é o servidor. O __name__ só diz ao Flask "o projeto começa neste arquivo".
📍A linha com @ é um aviso grudado na função de baixo: "quando alguém pedir a URL /, chama ela". Cada URL do site vai ter uma dessas.
🐍Uma função Python normal, como as do bootcamp. O nome home é escolha sua — quem manda é o @app.route de cima.
📦O return é a response! O que a função devolve é exatamente o que o navegador recebe e mostra.
🔌Liga o servidor e deixa de plantão, esperando requests. O debug=True faz ele reiniciar sozinho quando você salva o arquivo. 🙌
💡 Rota

O par @app.route("/") + def funcao() se chama rota: a ligação entre uma URL e a função Python que responde por ela. Grava essa palavra — ela é o coração do Flask.

render_template: servindo sua página de verdade
Juntando as duas metades da aula

Devolver uma frase é bonitinho, mas você tem uma página HTML inteira pronta! Será que dá pra devolver ela? Até dá… assim… 😬

a ideia ruim ❌ Python 
def home():
    return "<!DOCTYPE html><html><head><title>Minha Loja</title>..."

HTML misturado com Python vira uma sopa impossível de manter. O Flask tem o caminho certo: cada coisa no seu arquivo. Python no app.py, HTML numa pasta especial chamada templates:

📁 loja/ ├── 📁 venv/ ← o PyCharm criou (não mexe) ├── 🐍 app.py └── 📁 templates/ ← botão direito → New → Directory (nome EXATO!) └── 🧱 index.html ← arraste sua página pra cá

Significa: "Flask, abre a pasta templates, pega o index.html e manda ele como response". O navegador recebe seu HTML e renderiza — exatamente como na Forja de Tags lá de cima. 🪄

BugZilla apareceu: TemplateNotFound!
O erro mais clássico do primeiro dia de Flask
navegador — tela vermelha de erro erro 
jinja2.exceptions.TemplateNotFound: index.html

Tradução: "procurei o index.html na pasta templates e não achei". 99% das vezes é um destes três:

① a pasta chama template (sem o s) ou Templates (maiúscula) — tem que ser templates, exatinho;
② o arquivo ficou fora da pasta;
③ a pasta templates foi criada no lugar errado (ela mora do LADO do app.py).

👆 clica em um botão do navegador pra disparar um request
O cardápio do garçom 📋

As rotas são o cardápio do seu servidor: pediu /, sai o prato home(); pediu /sobre, sai o sobre(). Pediu algo fora do cardápio? O garçom devolve 404 — "não temos isso, chefe". Lembra das 4 abas do seu app_loja.py no Streamlit? Aqui, cada aba vai virar uma rota com URL própria.

👨‍🏫
Bora criar a página /sobre
Uma rota nova + um template novo

1. Crie templates/sobre.html (pode copiar o esqueleto do index.html e trocar o conteúdo do body):

loja/templates/sobre.html (o body) HTML 
<h1>ℹ️ Sobre a loja</h1>
<p>Loja criada por MIM, com Python, num curso da programa AI. 😄</p>
<p><a href="/">← voltar pro início</a></p>

2. No app.py, adicione a rota nova embaixo da primeira (e antes do app.run):

loja/app.py (adicione este bloco) Python 
@app.route("/sobre")
def sobre():
    return render_template("sobre.html")

3. Salve e visite localhost:5000/sobre 🎉 Depois volta pro index.html e planta um link lá (olha a tag <a> brilhando!):

loja/templates/index.html (no fim do body) HTML 
<p><a href="/sobre">Conheça a loja →</a></p>
🤯
Parou pra pensar? Você acabou de fazer um site com navegação entre páginas. Clicou no link → request pro /sobre → Flask chama sobre() → response com a página. O ciclo completo, rodando na sua máquina.

Bug 1 — "No module named 'flask'"
Mas eu instalei! Instalou… em outro lugar.
janela Run erro 
Traceback (most recent call last):
  File "app.py", line 1, in <module>
    from flask import Flask
ModuleNotFoundError: No module named 'flask'

O Python que rodou não é o do projeto — ou o Flask foi instalado fora dele. Os dois culpados de sempre:

① você rodou o pip install flask num terminal do sistema (fora do PyCharm), sem o (venv) na linha;
② o projeto está usando outro interpretador (acontece quando se abre a pasta por Open em vez de criar por New Project).

💊 Remédio: abra o Terminal do PyCharm (Alt+F12), confirme o (venv) no começo da linha e rode pip install flask de novo. Se persistir, confira em Settings → Project → Python Interpreter se o interpretador é o venv do projeto loja.

🐛
Bug 2 — TemplateNotFound: index.html
O hit do dia (você já conhece esse)

O Flask só procura templates na pasta templates, com esse nome exato, morando do lado do app.py. Checklist relâmpago: nome da pasta tem s no final? é tudo minúsculo? o arquivo está dentro dela? a pasta está no lugar certo?

🐛
Bug 3 — o dinossauro 🦖 em localhost:5000
"Este site não pode ser alcançado"

Você JÁ SABE o que isso significa (lembra da máquina Pedido ao Vivo?): o request saiu, mas não tinha servidor ligado pra atender. O app.py não está rodando — ou você clicou no ⏹ sem perceber, ou o app quebrou ao iniciar (aí tem um traceback vermelho te esperando na janela Run!).

💊 Remédio: olhe a janela Run: o Running on http://127.0.0.1:5000 está lá e o ⏹ vermelho está aceso? Se não, é só apertar o ▶ de novo.

🎁
Bônus raro — "Address already in use": significa que já TEM um servidor na porta 5000 — quase sempre uma aba antiga da janela Run que ficou rodando. Olhe as abas do Run (ou o ⏹ aceso) e pare a antiga antes de rodar de novo.
