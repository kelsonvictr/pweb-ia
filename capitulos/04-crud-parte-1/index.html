💡 Por que separar app.py e banco.py?

Poderia estar tudo no app.py? Poderia — e viraria uma sopa. Separando, cada arquivo tem UM assunto: app.py fala com o navegador, banco.py fala com o banco. Rota nunca escreve SQL; função de banco nunca renderiza template. Quando o sistema crescer (e ele cresce amanhã), você agradece.

📦
banco.py: a cozinha em duas funções
Funções do bootcamp + ritual do Dia 3 = a camada de dados

Primeiro passo do dia: reabra o projeto loja no PyCharm (File → Open Recent) e traga o criar_banco.py do treino-sql — pode copiar e colar o arquivo direto na árvore, com Ctrl+C/Ctrl+V. Rode UMA vez (▶) e o loja.db da Loja nasce ali. Depois, crie o banco.py — acompanhe o destaque:

loja/banco.py Python 
import sqlite3 def listar_produtos():    conexao = sqlite3.connect("loja.db")
    cursor = conexao.cursor()
    cursor.execute("SELECT * FROM produtos")
    produtos = cursor.fetchall()
    conexao.close()    return produtos def cadastrar_produto(nome, preco, qtd):    conexao = sqlite3.connect("loja.db")
    cursor = conexao.cursor()
    cursor.execute(
        "INSERT INTO produtos (nome, preco, quantidade) VALUES (?, ?, ?)",
        (nome, preco, qtd)
    )
    conexao.commit()
    conexao.close()
📦Só o sqlite3 — este arquivo nem sabe que o Flask existe. Cozinha não atende mesa.
📋listar_produtos() — uma função como as do bootcamp: nome claro, um trabalho só.
🔁O ritual completo do Dia 3, inteirinho dentro da função: abre, consulta, fecha. Cada chamada é autossuficiente.
🎁return produtos — devolve a lista de tuplas pra quem chamou (o app.py, daqui a pouco).
➕cadastrar_produto(nome, preco, qtd) — os parâmetros vêm do formulário. Repara: a função não sabe DE ONDE vêm. Nem precisa.
🛡️INSERT com ? ? ? (sempre!) e commit (escreveu? carimba!). Os dois mantras do Dia 3, agora trabalhando pra Loja.
🧠

@app.route("/produtos/novo", methods=["GET", "POST"])
def novo_produto():
    if request.method == "POST":
        nome  = request.form["nome"]
        preco = float(request.form["preco"])
        qtd   = int(request.form["qtd"])
        banco.cadastrar_produto(nome, preco, qtd)
        return redirect("/produtos")

    return render_template("novo.html")

💡 POST-redirect-GET (PRG), o padrão profissional

F5 = "repita o último request". Se o último foi um POST, o navegador reenvia o cadastro → produto duplicado. Com o redirect, o último request vira um GET inofensivo — F5 à vontade, nada duplica. Uma linha (return redirect(...)) e o bug morre pra sempre. Recarregou, não duplica.

@app.route("/produtos/novo", methods=["GET", "POST"])
def novo_produto():
    if request.method == "POST":
        nome = request.form["nome"].strip()

        if nome == "":
            return render_template("novo.html",
                                   erro="O nome não pode ficar vazio!")

        preco = float(request.form["preco"])
        qtd   = int(request.form["qtd"])
        banco.cadastrar_produto(nome, preco, qtd)
        return redirect("/produtos")

Bug 1 — o cadastro que se multiplica
3 Caixas de Som iguais no estoque?!

Sintoma: produtos duplicados misteriosamente. Causa: rota de cadastro sem redirect + usuário apertando F5 (você VIU na máquina). O navegador reenviou o POST — e cada reenvio é um INSERT novo.

💊 Remédio: depois de gravar, SEMPRE return redirect("/produtos"). E pra limpar as duplicatas que já nasceram? Você aprendeu no Dia 3: DELETE FROM produtos WHERE id = ? — o id certo da linha sobrando. 😉

🐛
Bug 2 — o ? esquecido
Funcionou nos testes… e explodiu com o produto "Fone d'ouvido"
terminal erro 
# alguém escreveu: f"INSERT ... VALUES ('{nome}', ...)"
sqlite3.OperationalError: near "ouvido": syntax error

A f-string no SQL passou nos testes… até chegar um nome COM ASPA (d'ouvido) — a aspa quebrou a string SQL. E lembra: se em vez de quebrar, o texto fosse malicioso, seria injection.

💊 Remédio: o mantra do Dia 3 vale dobrado agora que o dado vem de estranhos: valor de fora → placeholder ?, sempre.
